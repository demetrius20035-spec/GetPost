# GetPost

Простой и удобный GUI-клиент для отправки HTTP-запросов — аналог Postman/Insomnia
на Python и Qt. Позволяет организовывать запросы в рабочие пространства и папки,
отправлять их с произвольными параметрами и просматривать ответы с подсветкой
синтаксиса.

> В репозитории также есть полноценный **консольный клиент** —
> [`getpost.py`](getpost.py) (см. раздел [Консольный клиент (CLI)](#консольный-клиент-cli)).
> Он использует то же ядро, что и GUI, и умеет запускать сохранённые в Workspace запросы.

## Возможности

- **Рабочие пространства (Workspaces)** — создание, переименование, удаление;
  список доступен в левой панели; при запуске открывается последнее
  использованное пространство.
- **Папки** — неограниченное количество, вложенность до 2 уровней; создание,
  переименование, удаление.
- **Запросы** с полным набором параметров:
  - метод (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`);
  - URL с поддержкой переменных вида `{{base_url}}`;
  - заголовки (Headers) — таблица «ключ-значение»;
  - параметры запроса (Query Params) — таблица «ключ-значение»;
  - тело (Body): `raw` (Text/JSON/XML), `form-data`, `x-www-form-urlencoded`;
  - авторизация: `No Auth`, `Basic`, `Bearer`.
- **Отправка и просмотр ответа**: статус (например, `200 OK`), заголовки,
  тело с подсветкой JSON/XML и форматированием (Pretty), время выполнения и
  размер ответа. Запрос выполняется в фоновом потоке — интерфейс не «зависает».
- **Переменные окружения** на уровне Workspace (`{{var}}`), подставляются в URL,
  заголовки, параметры, тело и поля авторизации.
- **Автосохранение** всех данных в JSON. Сброс конфигурации к значениям по
  умолчанию из меню.
- **Кроссплатформенность**: Windows, macOS, Linux. Поддержка обоих биндингов Qt
  (PySide6 и PyQt6).

### Надёжность и безопасность

- **Секреты не утекают**: пароли, токены и переменные, помеченные как секретные
  (плюс распознанные по имени — `token`, `api_key`, `password`…), **не попадают
  в экспорт**. Файл для обмена безопасно передавать; включить секреты можно
  явно — для личной резервной копии. Значения маскируются в редакторе окружений.
- **Отмена действий** (`Ctrl+Z` / `Ctrl+Shift+Z`): удаление, перемещение,
  копирование, переименование, перетаскивание и правки — всё обратимо.
- **Ошибки сохранения видны**: если диск полон или нет прав, приложение
  сообщает об этом, а не показывает «Сохранено». Перед перезаписью создаётся
  резервная копия `*.json.bak`, в файлах есть `schema_version`.
- **Отмена запроса**: во время отправки кнопка «Send» превращается в «Cancel».
- **Ограничения**: тело ответа читается потоком и не более 16 МБ, история
  ответов ограничена по числу и по памяти (у старых записей тело выбрасывается).
- **Keep-alive**: запросы идут через общую `requests.Session` — соединения
  переиспользуются, cookies сохраняются между запросами.

### Организация и авторизация

- **Наследование от папки**: папка задаёт базовый URL, общие заголовки и
  авторизацию — вложенные запросы применяют их, не дублируя. Запрос может
  переопределить любой заголовок; для авторизации выбирается тип
  «Наследовать от папки» (по умолчанию у новых запросов). Папки с настройками
  помечены в дереве значком ⚙, а под строкой URL видно, что именно унаследовано.
- **Авторизация**: `No Auth`, `Basic`, `Bearer`, **API Key** (в заголовок или
  query-параметр) и **OAuth 2.0 client credentials** — токен запрашивается
  автоматически перед отправкой и кэшируется до истечения срока.
- **GraphQL**: отдельный тип тела с полями Query и Variables (отправляется
  как JSON `{"query": ..., "variables": ...}`).
- **Массовое редактирование таблиц**: кнопка «Текстом» превращает таблицу
  «ключ-значение» в текст (`Content-Type: application/json` построчно) — удобно
  вставлять сразу все заголовки из DevTools. Строка с `#` — выключенная пара.
- **Динамические переменные**: `{{$uuid}}`, `{{$timestamp}}`, `{{$isoTimestamp}}`,
  `{{$date}}`, `{{$randomInt(1,100)}}`, `{{$randomString(16)}}`. Переменные могут
  ссылаться друг на друга (`{{url}}` → `{{host}}/api`) — раскрываются рекурсивно
  с защитой от циклов.
- **Cookies**: сохраняются между запусками, есть просмотр и удаление
  («Файл → Cookies…»).
- **Тема и настройки** («Файл → Настройки…», `Ctrl+,`): светлая или тёмная тема,
  тайм-аут по умолчанию, прокси, лимит размера ответа, глубина истории.
- **Сравнение ответов**: кнопка «Сравнить…» над историей показывает различия
  двух ответов (статус, время, заголовки и тело; JSON нормализуется, чтобы
  порядок ключей не создавал ложных различий).

### Расширенные возможности

- **Импорт/экспорт** для обмена: любой Workspace, папку или запрос можно
  выгрузить в самодостаточный файл `*.getpost.json` (правый клик → «Экспортировать…»
  или «Файл → Экспорт/Импорт», `Ctrl+O`) и импортировать на другой машине — при
  импорте идентификаторы перегенерируются, существующие данные не затираются.
- **Цепочки запросов без скриптов** (вкладка «Capture»): после ответа значения
  записываются в переменные — например, `access_token` из ответа «Login»
  попадает в `{{token}}`, и остальные запросы используют его автоматически.
  Источники: путь по JSON (`data.items[0].id`), заголовок, код статуса, тело.
- **Генерация кода** (`Ctrl+G`): cURL, Python (requests), JavaScript (fetch),
  HTTPie — с копированием в буфер и сохранением в файл.
- **Быстрый переход** (`Ctrl+P`): поиск запроса по имени, пути и URL
  с нестрогим совпадением.
- **Подсветка неразрешённых переменных**: если в запросе есть `{{var}}`, которой
  нет в активном окружении, редактор предупредит до отправки.
- **Вкладка «Request»**: показывает, что реально ушло на сервер (итоговый URL,
  заголовки, тело, настройки редиректов и TLS) — отладка без догадок.
- **Загрузка файлов** в `form-data`: кнопка 📎 в строке поля (значение вида
  `@путь`, как в CLI).
- **cURL**: «Copy as cURL» (правый клик по запросу) и импорт запроса из команды
  `curl` (меню «Запрос → Импорт из cURL…»).
- **Окружения (environments)**: несколько именованных наборов переменных
  (например, `Default`/`Prod`) с переключателем активного окружения в левой
  панели и менеджером в «Файл → Окружения и переменные…».
- **URL ↔ Params**: двусторонняя синхронизация строки URL и таблицы query‑параметров.
- **Параметры запроса** (вкладка «Options»): следовать редиректам, проверять
  TLS‑сертификат, индивидуальный тайм‑аут.
- **Богатый просмотр ответа**: поиск по телу, перенос строк, копирование и
  сохранение в файл, вкладка **Cookies**, вкладка **Preview** (рендер HTML и
  изображений), **история** последних ответов на запрос.
- **Работа с деревом**: дублирование запросов/папок, **перемещение и
  копирование между папками** (контекстное меню «Переместить в…»/«Копировать в…»),
  перетаскивание (drag & drop) с соблюдением лимита вложенности, горячие клавиши
  (`Ctrl+Enter` — отправить, `Ctrl+N` — запрос, `Ctrl+Shift+N` — папка,
  `Ctrl+D` — дублировать, `Del` — удалить, `Ctrl+S` — сохранить).
- **Удобные заголовки**: новый запрос предзаполняется частыми заголовками
  (выключены — достаточно поставить галочку), плюс кнопка «＋ Частый заголовок»
  для быстрого добавления (`Content-Type`, `Accept`, `Authorization` и др.).
- **Оформление**: лёгкая пастельная светлая тема с акцентной кнопкой «Send».

## Требования

- Python **3.8+** (разрабатывалось и тестировалось на 3.11).
- `PySide6` **или** `PyQt6`.
- `requests`.

## Установка

```bash
# (рекомендуется) виртуальное окружение
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

Либо установить как пакет — тогда появятся команды `getpost` (CLI) и
`getpost-gui` (интерфейс):

```bash
pip install -e ".[gui]"     # с PySide6; для PyQt6: pip install -e ".[pyqt]"
```

На Linux Qt дополнительно нужны системные библиотеки:
`sudo apt install libegl1 libgl1 libxkbcommon0 libdbus-1-3`.

## Запуск

```bash
python run_gui.py
# или
python -m getpost_gui
```

Выбрать конкретный биндинг Qt можно переменной окружения:

```bash
GETPOST_QT_API=PyQt6 python run_gui.py
```

## Где хранятся данные

По умолчанию — в каталоге `~/.getpost`:

```
~/.getpost/
├── workspaces/
│   ├── <id>.json      # по одному файлу на рабочее пространство
│   └── ...
└── settings.json      # глобальные настройки (последний Workspace, геометрия окна)
```

Каталог можно переопределить переменной окружения `GETPOST_CONFIG_DIR`:

```bash
GETPOST_CONFIG_DIR=./config python run_gui.py
```

Файлы Workspace именуются по идентификатору, поэтому переименование не вызывает
конфликтов. Запись выполняется атомарно (через временный файл), что защищает
данные от повреждения при сбое.

## Краткое руководство

1. При первом запуске создаётся демонстрационное пространство **My Workspace** с
   переменной `base_url = https://httpbin.org` и примером запроса.
2. **Создание элементов** — кнопки «+ Папка» / «+ Запрос» над деревом или правый
   клик по дереву (контекстное меню). Переименование — двойной клик или `F2`.
3. **Переменные Workspace** — меню `Файл → Переменные…` (или `⋮` рядом со списком
   пространств). Используйте их как `{{имя}}` в любых полях запроса.
4. **Отправка** — кнопка **Send**, `Enter` в поле URL или `Ctrl+Enter`.
5. **Ответ** отображается справа: вкладки «Response» (тело, переключатель
   Pretty/Raw), «Headers», «Time».

## Консольный клиент (CLI)

`getpost.py` — функциональный HTTP-клиент для терминала, использующий то же
ядро, что и GUI (сборка запроса, подстановка переменных, доступ к сохранённым
Workspace).

```bash
python getpost.py <METHOD> <URL> [опции]     # или: python getpost.py send ...
python getpost.py run <Workspace> <Запрос>   # запустить сохранённый запрос
python getpost.py ls [Workspace]             # список Workspace / их содержимого
python getpost.py export <Workspace> [--request N|--folder N] [-o файл]
python getpost.py import <файл> [--into <Workspace>]
python getpost.py code <Workspace> <Запрос> --lang python|javascript|httpie|curl
```

Основные возможности:

- методы `GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS`;
- заголовки `-H 'K: V'`, query-параметры `-q k=v` (повторяемые);
- тело: `-d/--data` (в т.ч. `@file` и `@-` из stdin), `--json`,
  `-F/--form` (urlencoded), `--multipart` (в т.ч. загрузка файла `k=@path`);
- авторизация: `-u user:pass` (Basic), `--bearer TOKEN`;
- переменные `--var k=v` для `{{подстановки}}` (или `--use-workspace NAME`);
- управление: `--timeout`, `--no-redirect`, `-k/--insecure`, `--proxy`;
- вывод: цветной JSON, `-i`/`-I` (заголовки), `-v` (детали запроса),
  `-s` (тихо), `--raw`, `-o file` (сохранить тело), `--fail` (код возврата по HTTP-ошибке).

Примеры:

```bash
# GET с красивым цветным JSON
python getpost.py GET https://httpbin.org/get

# POST с JSON и Bearer-токеном
python getpost.py POST https://httpbin.org/post --json '{"a":1}' --bearer TOKEN

# Переменные и заголовки
python getpost.py GET '{{base}}/items' -H 'X-Key: 1' -q page=2 --var base=https://api.test

# Загрузка файла (multipart)
python getpost.py POST https://httpbin.org/post --multipart file=@./report.pdf

# Запуск сохранённого запроса из Workspace (создан в GUI)
python getpost.py ls
python getpost.py run "My Workspace" "Get IP"

# Обмен: экспорт и импорт
python getpost.py export "My Workspace" -o my.getpost.json
python getpost.py export "My Workspace" --request "Get IP" -o req.getpost.json
python getpost.py import my.getpost.json                 # новый Workspace
python getpost.py import req.getpost.json --into "My Workspace"
```

Полная справка — `python getpost.py --help` (и `... send --help`).

## Архитектура

Проект построен по схеме **MVC** и разделён на независимые слои:

```
getpost_gui/
├── qtcompat.py        # слой совместимости PySide6/PyQt6
├── models.py          # модель: Workspace → Folder → Request (без Qt)
├── storage.py         # сохранение/загрузка в JSON, автосейв (без Qt)
├── variables.py       # подстановка {{var}} (без Qt)
├── http_client.py     # сборка и выполнение запроса (тестируемо, без Qt)
├── curl.py            # импорт/экспорт в формате curl (тестируемо, без Qt)
├── codegen.py         # генерация кода: Python/JS/HTTPie (без Qt)
├── capture.py         # извлечение значений из ответа в переменные (без Qt)
├── inheritance.py     # наследование настроек от папок (без Qt)
├── oauth.py           # OAuth2 client credentials + кэш токенов (без Qt)
├── cookies.py         # перенос cookie jar между сессией и диском (без Qt)
├── diffing.py         # сравнение двух ответов (без Qt)
├── share.py           # импорт/экспорт элементов в *.getpost.json (без Qt)
├── controller.py      # единая точка изменений модели + Undo/Redo (QUndoStack)
├── runner.py          # выполнение запроса в фоновом потоке (QThread) + отмена
├── highlighter.py     # подсветка синтаксиса JSON/XML
├── theme.py           # пастельная светлая тема (палитра + QSS)
├── app.py             # точка входа
└── views/             # представление (GUI)
    ├── main_window.py     # компоновка панелей, меню, автосейв, отправка
    ├── sidebar.py         # дерево + DnD, окружения, дублирование, cURL
    ├── request_editor.py  # редактор (Params/Headers/Body/Auth/Options, URL↔Params)
    ├── response_view.py   # ответ (Response/Preview/Headers/Cookies/Time, поиск, история)
    ├── widgets.py         # таблица «ключ-значение»
    └── dialogs.py         # окружения, импорт/экспорт cURL
```

Вся бизнес-логика (модели, хранилище, подстановка переменных, сборка запроса)
не зависит от Qt, поэтому легко тестируется и может быть переиспользована.

## Тесты

Проект покрыт **300 тестами** на стандартном `unittest` — и логика без GUI
(модели, хранилище, переменные, сборка запроса, curl, codegen, capture,
наследование, OAuth2, cookies, diff, CLI), и сам интерфейс
(в offscreen-режиме, без реального дисплея):

```bash
python -m unittest discover -s tests -v
```

Тесты интерфейса пропускаются, если Qt не установлен, поэтому набор проходит и в
окружении без GUI. Те же команды выполняются в CI
(см. `.github/workflows/tests.yml`) на Python 3.9 и 3.12.

## Намеренные ограничения

Чтобы приложение оставалось простым, **не** реализованы: пред-/пост-скрипты и
тесты запросов (как в Postman), импорт коллекций Postman/OpenAPI/HAR,
браузерные потоки OAuth 2.0 (authorization code) и генерация JWT, мониторинг и
автоматизация запросов, gRPC/WebSocket.
